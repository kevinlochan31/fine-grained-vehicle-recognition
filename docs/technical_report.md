## 1. Problem Understanding & Solution Strategy

* **Core Technical Challenge:** Recognise the **make, model and year** of a car (196 Stanford Cars
  classes, 16,185 images, only 24-68 training images per class) and localise it with a bounding box.
  The main difficulty is that many classes are near-identical siblings: Audi S5 vs A5, Express Van vs
  Express Cargo Van, Dodge Caliber 2007 vs 2012. The system also has to stay reliable under:
  - darkness, over-exposure, noise and blur;
  - low resolution;
  - rotation and viewpoint changes;
  - partial occlusion;
  - **bad input**: photos with no car, and cars that are not among the 196 classes.

  Constraints: the public URL must answer within about 10 s, run on a laptop GPU (RTX 5060, 8 GB) or a
  CPU-only free host, and fit in a small model footprint.

* **Proposed Methodology:**
  - A fine-tuned **YOLO11s** finds the car. A **CLIP vehicle gate** rejects non-car images. The detected
    region is classified by a calibrated **ensemble of ConvNeXt-Tiny and a robustly fine-tuned CLIP
    ViT-B/16**.
  - The pipeline is **adaptive**. Classical enhancement (gamma, CLAHE, denoising, upscaling) is triggered
    only when measured image statistics call for it, and is added as a second view rather than replacing
    the original.
  - Confidence is calibrated, and the answer backs off hierarchically: class → make + model → make →
    "unknown".
  - Cars outside the 196 classes are detected and answered responsibly ("make first").

  This beats static baselines because a fixed enhancement hurt clean images (measured), and a closed-set
  classifier always forces one of 196 labels, even onto flowers or a 2024 car.

## 2. Technical Architecture & Implementation

> Architecture diagram: `docs/architecture.png` (generated by `docs/make_architecture.py`).
> Full design: `docs/design_document.md`.

### 2.1 Classical Algorithmic Baseline (`src/classical.py`)
* **Algorithms Utilised:**
  - *Image-quality analysis:* brightness, contrast, Immerkaer noise σ, Laplacian sharpness, resolution.
  - *Enhancement:* adaptive gamma, **CLAHE** on the L channel, **bilateral** edge-preserving denoising,
    bicubic upscaling.
  - *Edges and contours:* auto-threshold **Canny**, morphological closing, contours, Hu moments.
  - *Features:* **HOG** (shape), uniform **LBP** (texture), HSV histogram + colour moments, Sobel
    edge-orientation histogram, geometric features (aspect ratio, extent, solidity, circularity).
  - *Classifier and ROI:* PCA + logistic regression; an edge/contour **ROI extractor** serves as the
    classical detector and as a fallback.
* **Adaptive Selection Logic:** parameters come from the measured statistics of each image.
  - Gamma is applied only when mean brightness is below 70.
  - The CLAHE clip limit grows as contrast drops.
  - Bilateral filtering is applied only when the noise σ is above 12.
  - Upscaling is applied only for small crops.
  - Canny thresholds are set from the median intensity.

  On normal photos enhancement is usually a no-op, so clean inputs are not harmed.

### 2.2 Deep Learning Pipeline
* **Model Architecture:**
  - **Detector:** YOLO11s (COCO-pretrained), fine-tuned 15 epochs on the Stanford boxes as one class
    "car" (`scripts/train_detector.py`). Chosen for real-time speed; fine-tuning teaches it the dataset's
    "main car, tight box" convention.
  - **Classifier 1:** ConvNeXt-Tiny (ImageNet-22k pretrained), fine-tuned at 384 px for 30 epochs
    (`scripts/train_classifier.py`). Strong fine-grained accuracy at 28 M parameters, small enough for CPU
    hosting.
  - **Classifier 2:** CLIP ViT-B/16 (LAION-2B pretrained), fine-tuned 15 epochs (`scripts/train_clip.py`).
    Its 196-way head is initialised from CLIP text embeddings of the class names, and layer-wise LR decay
    (0.75) is used. Chosen for its robustness to real-world photos.
  - **Vehicle gate and open-set naming:** zero-shot CLIP ViT-B/16 with no training (`src/openvocab.py`),
    using car vs. non-car prompts and a 954-model catalogue.
* **Loss Functions & Training:**
  - Cross-entropy with **label smoothing 0.1**, AdamW with **weight decay 0.05**, 1-epoch warm-up +
    cosine schedule, bf16 mixed precision. ConvNeXt also uses **stochastic depth 0.2**.
  - Augmentation:
    - *ConvNeXt:* random resized crop, flip, colour jitter, greyscale, blur, rotation, random erasing,
      down-scaling.
    - *CLIP (harsher):* gamma darkening and over-exposure, 12-45% down-scaling, sensor noise, JPEG
      quality 15-90, perspective warp, rotation, occlusion.
  - Data: Stanford Cars only, split into train 7,356 / validation 788 (stratified 10% of the official
    training set) / test 8,041 (official split, never used for training or tuning).
  - The best checkpoint is selected on validation.

### 2.3 Hybrid Integration & Adaptive Mechanism (`src/pipeline.py`)
* **Fusion Strategy:**
  1. Classical image statistics decide whether to enhance. If YOLO finds no box, the whole image is
     enhanced and YOLO is retried.
  2. The classifiers see the **detected region** (+8% context), not the whole image.
  3. The classically enhanced crop is used as a **second view** and averaged with the original, each with
     flip test-time augmentation.
  4. The two networks are **temperature-calibrated** (T = 0.65 / 0.5) and averaged 0.3 / 0.7. All weights
     were chosen on validation; classical-feature late fusion was tested and given weight 0 (no gain).
* **Decision Logic:**
  * **Vehicle gate.** The image is accepted if P(car) ≥ 0.9, or if P(car) ≥ 0.5 and the YOLO box
    confidence is ≥ 0.3. Otherwise the answer is **"No car detected"**.
  * **Hierarchical back-off.** The threshold t = 0.67 was chosen on validation as the lowest giving
    ≥ 98.5% precision.
    - Below t, the system reports "make + model (year uncertain)" or "make only".
    - The big title never shows a model the system did not commit to.
  * **Open-set check and responsible answer.** CLIP on the crop flags cars outside the 196 classes. For
    those, and for cars the classifier is unsure about at every level, the answer is built **make
    first** (make probabilities from the classifier and CLIP fused 50/50):
    - a catalogue model is named only when CLIP is ≥ 80% sure;
    - otherwise the answer is **"<make>, model not recognised"** (make ≥ 40%);
    - or **"Unknown car (outside the supported classes)"** when even the make is unclear.

## 3. Experimental Benchmarks & Evaluation

All numbers are on the official **8,041-image test split**. Full tables are in `eval_P5_T80.md`
and `results/*.json`.

### 3.1 Quantitative Benchmarks

| Approach / Model Variant | Top-1 ↑ | Top-5 ↑ | Class-aware mAP@0.5 ↑ | Mean IoU ↑ | Latency (GPU) |
| :--- | :---: | :---: | :---: | :---: | :---: |
| **Classical Baseline** (classical ROI / HOG+LBP+colour+edge+geometry → PCA+LogReg) | 14.53% | 32.94% | 0.072 | 0.654 | ~15 ms features + 0.02 ms classifier |
| **Deep Learning Only** (YOLO11s crop → ConvNeXt-T) | 94.52% | 99.19% | 0.927 | 0.954 | ~14 ms (8.0 detector + 5.5 classifier) |
| **Proposed Hybrid System** | **95.90%** | **99.75%** | **0.944** | **0.954** | ~150-200 ms per full web request |

Further results:
- **Detector:** mAP@0.5 **0.989**, mAP@0.5:0.95 **0.931**, mean IoU **0.954**. The COCO-pretrained
  YOLO11n gets 0.854 / 0.784 / 0.944.
- **Calibration:** expected calibration error (ECE) is 0.011 for the hybrid, vs 0.017 for deep only.
- **Make accuracy:** 99.10%.
- **Strict top-1 with unseen routing on:** 95.45%.

**Optimisation:**

| ConvNeXt variant | Size | Test top-1 (1,500 subset) | Latency |
| :--- | :---: | :---: | :---: |
| FP32 | 106.8 MB | 93.87% | 8.2 ms GPU / 74.2 ms CPU |
| **FP16 (deployed)** | **53.4 MB** | 93.87% | **5.5 ms GPU** |
| **INT8 static quantisation (ONNX)** | **27.3 MB** | 93.73% | 40.6 ms CPU |
| 30% L1 pruning (no fine-tune) | 41.0 MB | 89.67% | - |

**Robustness** (end-to-end top-1 on 1,000 test images per condition):

| Condition | Deep | Hybrid |
| :--- | :---: | :---: |
| Very dark + noisy | 89.7% | **93.0%** |
| 8× low resolution | 75.8% | **82.7%** |
| 4× low resolution | 90.7% | **93.5%** |
| 15° rotation | 92.4% | **94.8%** |
| Perspective (viewpoint) | 94.2% | **95.2%** |
| 30% occlusion | **88.7%** | 87.5% |

**Bad input and unfamiliar cars:**
- **Vehicle gate:** accepts 99.89% of real cars and rejected all 16 non-car probe photos.
- **Unseen routing:** 80% of simulated unseen models are flagged, with 0.8% of known cars wrongly flagged.
- **Make-first rule vs the old rule** (simulated unseen cars):
  - car in the catalogue: wrong answers 25.9% → **17.4%**;
  - car not in the catalogue: wrong answers 66.4% → **34.6%**.

* **Analysis:**
  - **Classical vs deep:** hand-crafted features cannot separate 196 near-identical classes (14.5%), while
    transfer-learned deep models reach 94.5%.
  - **Hybrid gain:** the hybrid adds +1.4 points on clean images and much more on hard ones (+6.9 at 8×
    low resolution, +3.3 when very dark). The robust CLIP member gives most of it.
  - **Cost:** about 10× the latency of deep only, still far below the 10 s budget.
  - **Weak spot:** occlusion is the one condition without a gain (within the ±1 point noise at n = 1,000).

### 3.3 Ablation Study

| Variant (test top-1) | Top-1 | Δ vs full |
| :--- | :---: | :---: |
| Full hybrid | 95.90% | - |
| − robust CLIP fine-tune (ConvNeXt-only hybrid) | 94.62% | −1.28 |
| − flip TTA | 95.73% | −0.17 |
| − adaptive enhancement view | 95.86% | −0.04 |
| − classical feature fusion (weight 0 on validation) | 95.90% | 0.00 |
| Deep only (no TTA, no enhancement, no ensemble) | 94.52% | −1.38 |
| − detection crop (whole image → crop-trained CNN) | 90.32% | −5.58 |
| Oracle ground-truth box (deep) | 94.64% | +0.12 vs deep only |

Key findings:
- **Detection crop:** the largest single factor. Our detector crop matches oracle ground-truth boxes
  within 0.12 points.
- **Robust CLIP member:** the largest gain within the hybrid.
- **Fixed vs adaptive enhancement:** *replacing* the original crop with the enhanced one gave no gain on
  clean data and hurt dark images in an earlier version. *Adding* it as a view is what helps under hard
  conditions.
- **Classical feature groups** (validation): HOG alone gives 11.4%; removing HOG drops to 10.3%.

## 4. Failure Modes & Limitations

Nine cases are documented in `docs/design_document.md` §9; the main ones:

* **Observed Failure Case 1 – year / sibling confusion.** Of 330 test errors:
  - 66% are the right make with the wrong model (e.g. Audi S5 vs A5);
  - 12% are the right model with the wrong year (Dodge Caliber 2007 vs 2012).

  **Root cause:** the generations share the same body; the differences (lamps, badges) are a few pixels
  and vanish in side or rear views. **Mitigation:** the year-uncertain / make-only back-off; part-based
  attention on lamps and grille as future work.
* **Observed Failure Case 2 – non-car image named as a car.** In the first version, tulips were labelled
  "Lamborghini Gallardo". **Root cause:** the single-class detector fires on anything (0.53), and a
  closed-set softmax must pick one of 196 classes. **Mitigation (implemented):** the CLIP vehicle gate,
  which gives the tulips P(car) = 0.00003 → "No car detected".
* **Observed Failure Case 3 – unfamiliar car given a wrong name.** A Bugatti special edition was named
  "Ferrari F8 Tributo" (46%). **Root cause:** it is in neither the 196 classes nor the catalogue, and the
  open-set branch replaced the classifier's correct make (Bugatti, 67%) with CLIP's uncertain top model.
  **Mitigation (implemented):** the make-first rule → "Bugatti, model not recognised", best unconfirmed
  guess Bugatti Divo.
* **Observed Failure Case 4 – dataset label noise.** "Confident but wrong" predictions such as GMC
  Terrain vs label "Yukon", or Grand Cherokee vs label "Compass", turn out to be correct predictions on
  wrongly labelled test images. This caps the achievable accuracy.
* **Limitations:**
  - Year is learned only for the 196 classes (US market, 1991-2012).
  - About 20% of unseen models are not flagged.
  - Regional models (e.g. the Ford Figo) are missing from the catalogue.
  - Only one car per image is classified.
  - Robustness is measured on synthetic corruptions.

  No number-plate or person recognition is done.

## 5. Deployment & Quickstart Guide

### Quickstart Commands
```bash
# 1. Clone the repository and install dependencies
git clone <your-github-repo-url>
cd <repo-folder>
pip install -r requirements.txt

# 2. Run the web app (UI + REST API) and open http://127.0.0.1:7860
python app.py

# 3. Or with Docker
docker build -t p5-cars . && docker run -p 7860:7860 p5-cars

# 4. Reproduce all results (needs the Stanford Cars dataset in ~/cvh/data/raw, ~2.5 h on an RTX 5060)
python -m scripts.run_all
python -m scripts.write_report --team <TeamID> --usns "<USN1>,<USN2>,..."
```

### Deployment Format
* **Backend:** FastAPI + Uvicorn (`app.py`).
  - REST endpoints: `/api/analyze`, `/api/performance`, `/api/health`.
  - A single inference thread with GPU warm-up at start-up.
  - Upload limit 15 MB; readable error messages for bad files.
* **Frontend:** custom web UI "AutoLens" (`web/`, vanilla JS + Motion animations).
  - Upload / paste / camera input.
  - Loading, error, "no car", "unknown model" and low-confidence states.
  - Live classical vs deep vs hybrid comparison.
* **Packaging:** `modal_app.py` deploys the live demo on Modal (CPU container); the `Dockerfile` runs it on any Docker host (e.g. Hugging Face Spaces via `scripts/deploy_hf.py`).
  - Weights: PyTorch FP16, with an optional ONNX INT8 classifier (`CVH_BACKEND=onnx`).
  - The 165 MB CLIP weight file is tracked with Git LFS (`.gitattributes`).
