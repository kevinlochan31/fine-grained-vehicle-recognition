---

## 1. What the system does

Upload any photo and the system:

1. Checks the input (file type, size, blank image, greyscale/transparent images, very large images).
2. Decides whether there is a car at all; if not, answers **"No car detected"**.
3. Detects the car and draws its **bounding box**.
4. Predicts **make, model and year** (196 Stanford classes) with a calibrated **confidence score**.
5. If it is unsure, backs off to a safer answer: "make + model (year uncertain)", "make only", or
   "uncertain, see top-5".
6. If the car is not one of the 196 trained classes (or the classifier is too unsure), it answers
   responsibly, **make first**:
   - it names the model from a 954-model catalogue only when CLIP is at least 80% sure;
   - otherwise it reports **"<make>, model not recognised"**;
   - or **"Unknown car (outside the supported classes)"** when even the make is unclear.

   The best guess is still shown, clearly labelled "unconfirmed".
7. Shows the **intermediate image-processing steps** (enhancement, edges, contours, ROI, features).
8. Shows **classical vs deep vs hybrid** predictions side by side for the same photo.

## 3. Architecture (pipeline)

```
input -> validation -> image-quality analysis (brightness, contrast, noise, sharpness, size)
      -> YOLO11s car detector (retry on an enhanced image if nothing is found)
      -> CLIP vehicle gate  -- not a car --> "No car detected"
      -> ROI crop (+8% context)
      -> adaptive classical enhancement (gamma / CLAHE / bilateral / upscaling, only when needed)
      -> ConvNeXt-Tiny  +  robust CLIP ViT-B/16 fine-tune   (each with flip TTA, on original + enhanced view)
      -> temperature calibration -> weighted ensemble (0.3 / 0.7)
      -> hierarchical low-confidence back-off (threshold 0.67)
      -> open-set check (unseen model?) -> zero-shot naming over 954 models
      -> annotated output: box, label, confidence, top-5, intermediate steps
```

Diagram: `docs/architecture.png` (generated by `docs/make_architecture.py`).

## 4. Components

### 4.1 Classical computer vision (all mandatory items covered)

| Brief requirement | What we implemented |
|---|---|
| Preprocessing and normalisation | Mean/std normalisation; histogram equalisation; **adaptive** gamma, CLAHE, bilateral denoising and upscaling chosen from measured image statistics |
| Edge detection and contour analysis | Automatic Canny thresholds (median based), morphological closing, external contours, Hu moments |
| Colour and texture features | HSV joint histogram + colour moments; uniform LBP on a 2x3 grid; Sobel edge-orientation histogram |
| Region-of-interest extraction | Edge/contour-based ROI (classical detector, also a fallback) + ROI crop with context |
| Geometric feature analysis | Aspect ratio, edge density, contour extent, solidity, circularity, Hu moments |
| Shape | HOG (9 orientations, 8x8 cells) |

Classical classifier: features -> PCA -> logistic regression.

### 4.2 Deep learning

| Part | Details |
|---|---|
| Detector | **YOLO11s**, COCO-pretrained, fine-tuned 15 epochs on Stanford boxes as one class "car" |
| Classifier 1 | **ConvNeXt-Tiny** (ImageNet-22k pretrained), fine-tuned at 384 px, 30 epochs |
| Classifier 2 | **CLIP ViT-B/16** (LAION-2B pretrained), fine-tuned 15 epochs, head initialised from text embeddings of the class names |
| Vehicle gate + open-set naming | Zero-shot CLIP ViT-B/16 (no training) |

### 4.3 Hybrid integration

1. Detected region (not the whole image) is classified.
2. Classical enhancement is used as a second view and averaged with the original.
3. Flip test-time augmentation.
4. Calibrated ensemble of the two networks; classical-feature fusion weight tuned on validation (best = 0).
5. Low-confidence back-off.
6. "No car" gate and unseen-model check.

## 5. How we reduced overfitting and improved robustness

- **Transfer learning** from large pre-trained models (ImageNet-22k, LAION-2B).
- **Layer-wise learning-rate decay (0.75)** for CLIP so the general early layers change little.
- **Label smoothing 0.1**, **weight decay 0.05**, **stochastic depth 0.2** (ConvNeXt).
- **Warm-up + cosine** learning-rate schedule; **best checkpoint chosen on validation**.
- **Augmentation**:
  - ConvNeXt: random crops, flips, colour jitter, greyscale, blur, rotation, random erasing, down-scaling.
  - CLIP: harsher, including darkness and over-exposure, low resolution, sensor noise, JPEG damage,
    perspective change, rotation and occlusion.
- **Ensemble** of a CNN and a transformer, which make different mistakes.
- **Temperature scaling** so that confidence values are trustworthy.

### 6.4 Model efficiency - size and inference time

| Component | Params | Size | GPU latency | CPU latency |
|---|---|---|---|---|
| YOLO11s detector | 9.4 M | 18.3 MB | 8.0 ms | 38.5 ms |
| ConvNeXt-T FP16 (deployed) | 28.0 M | 53.4 MB | 5.5 ms | - |
| CLIP ViT-B/16 fine-tune FP16 (with flip TTA) | 86.3 M | 164.6 MB | 8.9 ms | 135 ms |
| CLIP gate + open-set naming | 86.2 M | - | 6.6 ms | 122 ms |
| Whole web request (GPU) | | | about 0.15-0.2 s | |

GPU: RTX 5060 Laptop (8 GB).

**Optimisation techniques (three applied):**

| ConvNeXt variant | Size | Test top-1 (1,500 subset) | Latency |
|---|---|---|---|
| FP32 | 106.8 MB | 93.87% | 8.2 ms GPU / 74.2 ms CPU |
| **FP16 reduced precision (deployed)** | **53.4 MB** | 93.87% (no loss) | **5.5 ms GPU** |
| **INT8 static quantisation (ONNX)** | **27.3 MB** (3.9x smaller) | 93.73% (-0.14) | 40.6 ms CPU |
| Pruning 30% (no fine-tune) | 41.0 MB compressed | 89.67% | - |
| Pruning 50% (no fine-tune) | 32.9 MB compressed | 16.00% | - |

Conclusion: FP16 halves the size with no loss and is deployed. INT8 is best for small devices. Pruning
without retraining is not worthwhile.

### 6.5 Robustness - performance under varying conditions

End-to-end on 1,000 random test images per condition. Strict scoring: "no car" and "unseen" answers
count as errors.

| Condition | Classical | Deep | **Hybrid** |
|---|---|---|---|
| Original | 5.0% | 94.7% | **94.8%** |
| Dark | 4.4% | 94.1% | **95.0%** |
| Very dark + noisy | 2.6% | 89.7% | **93.0%** |
| Overexposed | 4.3% | 93.4% | **93.8%** |
| Low resolution 4x | 2.3% | 90.7% | **93.5%** |
| Low resolution 8x | 2.5% | 75.8% | **82.7%** |
| 30% occlusion | 1.8% | **88.7%** | 87.5% |
| Gaussian noise | 3.7% | 93.2% | **94.5%** |
| Motion blur | 2.5% | 89.4% | **90.5%** |
| 15 degree rotation | 1.7% | 92.4% | **94.8%** |
| Perspective (viewpoint) | 3.7% | 94.2% | **95.2%** |

## 7. Ablation study

| Variant | Top-1 | Top-5 |
|---|---|---|
| Full hybrid | 95.90% | 99.75% |
| Without flip TTA | 95.73% | 99.73% |
| Without adaptive enhancement view | 95.86% | 99.75% |
| Without classical feature fusion | 95.90% | 99.75% |
| Without the CLIP fine-tune (ConvNeXt-only hybrid) | 94.62% | 99.17% |
| CLIP fine-tune alone | 95.68% | 99.76% |
| Deep only (no TTA, no enhancement, no ensemble) | 94.52% | 99.19% |
| Without the detection crop (whole image) | 90.32% | 97.44% |
| Oracle: ground-truth box crop | 94.64% | 99.22% |

Key findings:
- The robust CLIP member is the largest single gain (+1.3 points).
- Using the detected crop matters (+4.2 points vs the whole image).
- Our detector crop is as good as the ground-truth box.

Classical feature groups (validation top-1): HOG alone 11.42%; removing HOG drops to 10.28%; removing
edges or geometry leaves 14.59%. HOG is the most useful group, while colour alone is weak (4.82%) because each model comes in many
colours.

## 8. Error analysis and failure cases

330 hybrid errors out of 8,041 test images:
- 66.4%: right make, wrong model (e.g. Audi S5 vs A5).
- 11.8%: right make and model, wrong year.
- 21.8%: different make.

Top confusions:
- Audi TTS Coupe 2012 -> TT Hatchback 2011 (17)
- Dodge Caliber Wagon 2012 <-> 2007 (13 + 9)
- Chevrolet Express Van <-> Express Cargo Van (13 + 10)
- Audi S5 -> A5 Coupe (12)

| # | Failure case | Cause | Fix / mitigation |
|---|---|---|---|
| 1 | Year confusion (Bentley Continental GT 2012 vs 2007, Dodge Caliber 2012 vs 2007) | Generations look almost the same | "Year uncertain" back-off |
| 2 | "Confident but wrong" (GMC Yukon vs Terrain, Jeep Compass vs Grand Cherokee, Rolls-Royce Phantom vs Ghost) | **Dataset labelling mistakes**: the prediction is right, the label is wrong | Reported; caps the achievable accuracy |
| 3 | Multi-car or collage images | Only one car is annotated per image | Box ranked by confidence x size |
| 4 | Dark body-style variants (wagon vs sedan, coupe vs convertible) | The distinguishing part is in shadow | Hybrid enhancement; medium confidence |
| 5 | Tiny or low-resolution cars (Audi V8 vs Audi 100, 1994) | Same body; only the grille differs | Low-resolution augmentation (+6.9 points at 8x) |
| 6 | Tulips labelled "Lamborghini Gallardo" (first version) | The detector fires on anything; the classifier must pick 1 of 196 | **Fixed**: CLIP vehicle gate -> "No car detected" |
| 7 | 2024 Aston Martin labelled "Lamborghini" / "Hyundai Veloster" (first version) | The model is not in the 196 classes | **Fixed**: open-set check -> "Aston Martin Vantage (not in the 196 training classes)" |
| 8 | Bugatti special edition named "Ferrari F8 Tributo" (46%) | The model is not in the catalogue; the weak zero-shot guess overrode the correct make from the classifier (closest class: Bugatti Veyron) | **Fixed**: make-first rule -> "Bugatti, model not recognised", best unconfirmed guess Bugatti Divo |
| 9 | Ford Figo (Indian market) shown as "Ford Fiesta Sedan 2012" at 21% | The model is not in the 196 classes or the catalogue | **Fixed**: "Unknown car (outside the supported classes?)", Fiesta kept as an unconfirmed guess; adding regional models to the catalogue is future work |

Galleries: `results/failures/*.jpg`. All 9 cases are in the design document (section 9).

## 9. Web application (AutoLens)

- **Backend:** FastAPI (`app.py`).
  - Endpoints: `/api/analyze`, `/api/performance`, `/api/classes`, `/api/examples`, `/api/health`.
  - A single inference thread avoids GPU warm-up on every request.
- **Frontend:** custom HTML/CSS/JS (`web/`) with Motion (the JavaScript successor of Framer Motion).
  - Boot sequence and animated particle car.
  - HUD-style scanner with the bounding box, confidence ring and image-quality telemetry.
  - Top-5 candidates.
  - "Classical vs deep vs hybrid on your photo" comparison cards.
  - Intermediate-step layers.
  - Results charts.
  - Pipeline timeline.
- **States:** loading, error, "No car detected" (red), "Unseen model" (cyan), "Unknown model" (make only,
  amber), "Outside supported classes" (red), "Year uncertain", "Make only". In uncertain states the big
  title shows only what the system commits to, never a guessed model.
- **Inputs:** upload, paste or camera; JPG/PNG/WEBP up to 15 MB; 8 unseen test examples built in.
- **Run locally:** `python app.py` -> http://127.0.0.1:7860 (or `start_app.bat`, or the `Dockerfile`).

## 12. Limitations and ethics

**Limitations**
- Only the 196 Stanford classes (mostly US-market cars, 1991-2012) are recognised with year and high
  accuracy.
- Unseen models are named only if they are in the 954-model catalogue and CLIP is sure, and without a
  year; otherwise only the make (or nothing) is reported. About 20% of unseen models are not flagged and
  get the nearest trained class; this is the main remaining source of wrong answers on unfamiliar cars.
- The exact year is the weakest part, because many generations look identical.
- Only the main car in a photo is classified.
- Heavy occlusion and night photos with only headlights visible remain hard.
- Some test labels in the dataset are wrong, which caps the achievable accuracy.

**Ethics**
- No number-plate recognition, person identification or tracking.
- Not intended for surveillance of individuals.
- Dataset images keep their original licences.
